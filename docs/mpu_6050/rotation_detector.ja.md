# MPU6050::RotationDetector

`MPU6050::RotationDetector` は、MPU-6050 の選択した軸まわりの1回転を検出します。
PicoRuby/R2P2 上で、自転車のホイールやクランクの回転を検出する用途を想定しています。サンプリングループ中のメモリ確保を小さく保つため、履歴配列などは持たず、スカラー値だけを更新します。

主な検出方法はジャイロの積分です。加速度の位相は、ジャイロの動きがデッドバンド以下で、かつ加速度ベクトルが十分に信頼できる場合だけ、低速時のフォールバックとして使います。

## サンプルに必要な値

`update(sample)` は、次のメソッドを持つサンプルオブジェクトを受け取ります。

- `time_ms`: サンプル時刻。単位はミリ秒。
- `dt`: 前回サンプルからの経過時間。単位は秒。
- `gyro_x`, `gyro_y`, `gyro_z`: 各軸の角速度。単位は degrees per second。
- `accel_x`, `accel_y`, `accel_z`: 各軸の加速度。単位は g。
- `accel_saturated?`: 任意。`MPU6050` が返す飽和フラグ。true の場合、加速度の生値がセンサの上限付近にあります。
- `gyro_saturated?`: 任意。true の場合、ジャイロの生値がセンサの上限付近にあります。

`MPU6050#sample_now` は MPU オブジェクト自身を返します。そのため、検出器は配列やハッシュを作らずに、スカラーの reader だけで値を読めます。

## 軸の選択

検出器は軸を指定して作ります。

```ruby
detector = MPU6050::RotationDetector.new(:y, 120, 0)
```

選択した軸によって、積分するジャイロのチャンネルが決まります。

- `:x` は `gyro_x` を使う
- `:y` は `gyro_y` を使う
- `:z` は `gyro_z` を使う

加速度フォールバックでは、選択した軸に垂直な平面上で位相角を計算します。

- `:x`: `atan2(accel_y, accel_z)`
- `:y`: `atan2(accel_z, accel_x)`
- `:z`: `atan2(accel_x, accel_y)`

実機では、ホイールやクランクを回したときに `max_gyro_*` が最も大きい軸を選びます。たとえば `max_gyro_y` が `max_gyro_x` や `max_gyro_z` より明らかに大きいなら、`AXIS = :y` を使います。

## 検出の流れ

`update(sample)` は、毎回おおよそ次の順序で処理します。

1. `sample.time_ms` を読む。
2. 加速度サンプルが飽和しているか確認する。
3. 加速度位相が十分に信頼できるか確認する。
4. 使える場合だけ、加速度位相の差分を計算する。
5. `gyro_dps * dt` からジャイロ由来の角度差分を計算する。
6. ジャイロがデッドバンドを超えている場合は、ジャイロ由来の差分を優先する。
7. ジャイロ差分がゼロで、かつサンプルがスキップされていない場合だけ、加速度位相差分にフォールバックする。
8. 選択した差分を内部の積算角に加える。
9. 積算角が約1回転分に達したらイベントを返す。

ジャイロ由来の角度差分は、次の式で計算します。

```text
delta_angle_rad = gyro_dps * PI / 180 * dt
```

`delta_angle` の単位はラジアンです。1回転は約 `2 * PI` ですが、この検出器ではしきい値として `6.0` を使い、検出後に `2 * PI` で折り返します。小さな積分誤差で1回転を取り逃がしにくくするため、少し早めにイベントを出す設計です。

正方向の回転を検出した場合:

- `count` が 1 増える。
- `time_ms` にイベント時刻が入る。
- `update` は検出器自身を返す。

負方向の回転を検出した場合:

- `count` が 1 減る。
- `time_ms` にイベント時刻が入る。
- `update` は検出器自身を返す。

回転イベントがない場合、`update` は `nil` を返します。

## 方向と最小周期

コンストラクタの引数は次の通りです。

```ruby
MPU6050::RotationDetector.new(axis, min_period_ms, direction)
```

- `axis`: `:x`, `:y`, `:z`、または `0`, `1`, `2`。
- `min_period_ms`: 回転イベント間の最小時間。
- `direction`: `0` は両方向、`1` または `:positive` は正方向のみ、`-1` または `:negative` は負方向のみ。

`min_period_ms` は、物理的にありえない短時間の連続イベントを捨てるために使います。ホイールでは `120` ms が初期値として扱いやすいです。クランクでは、より大きい値が適している場合があります。

## ジャイロ積分

選択軸のジャイロ値は `gyro_value(sample)` で読みます。

ジャイロ由来の差分は、次の場合に無視されます。

- `dt` が `nil`、または 0 以下。
- `dt` が `max_dt_ms` より大きい。
- 選択軸の `gyro_dps` が `nil`。
- `gyro_dps` の絶対値が `gyro_deadband_dps` より小さい。

ジャイロのデッドバンドの初期値は `3.0` dps です。これは、静止時のノイズを回転として積分しないためのものです。

ライブラリ内の `max_dt_ms` の初期値は `250` ms です。検証用サンプルでは、USB出力などによる遅延を見つけやすくするために `50` ms を使っています。`dt_skipped?` が頻繁に true になる場合は、ループが遅いかログ出力が重すぎます。

## 加速度位相フォールバック

加速度フォールバックは、選択軸に垂直な平面上で重力方向の位相を見て、回転を推定します。

次の条件をすべて満たす場合だけ使われます。

- 加速度サンプルが飽和していない。
- 位相に使うベクトルの大きさが `accel_phase_min_g` 以上。
- ジャイロ差分がデッドバンド処理後にゼロ。
- `dt` が大きすぎるためにスキップされたサンプルではない。

`accel_phase_min_g` の初期値は `0.25` です。内部では `Math.sqrt` を呼ばないために、二乗値で比較します。

位相が有効でない場合:

- `phase_valid?` は `false` を返す。
- 保存していた前回位相をリセットする。
- そのサンプルでは加速度位相差分を使わない。

前回位相をリセットするのは重要です。リセットしないと、次に位相が有効になったとき、古い位相との差分で大きな誤検出が起きる可能性があります。

## 飽和の扱い

`MPU6050#sample` は、いずれかの加速度生値が設定した上限付近にある場合、`accel_saturated?` を true にします。

`accel_saturated?` が true の場合:

- `saturated?` は true を返す。
- 加速度位相を無視する。
- 前回の加速度位相をリセットする。
- ジャイロ積分は引き続き使える。

これにより、急な加速や振動を、回転位相の変化として誤検出しにくくします。

`gyro_saturated?` が true の場合は、clippingした角速度を積分すると回転数を過小評価するため、
そのサンプルのジャイロ積分を使いません。加速度位相が有効ならフォールバックし、加速度も
飽和していればそのサンプルでは角度を進めません。

## デバッグ値

検出器は、調整用に軽量なスカラー reader を提供します。

- `count`: 検出した回転数。
- `time_ms`: 最後にイベントを出した時刻。
- `gyro_dps`: 現在選択しているジャイロ軸の最新値。
- `delta_angle`: 最新の角度差分。単位はラジアン。
- `angle`: 現在の積算角。単位はラジアン。
- `phase`: 最新の加速度位相。単位はラジアン。
- `phase_valid?`: 現在の加速度位相が使えるか。
- `saturated?`: 現在のサンプルで加速度またはジャイロが飽和しているか。
- `gyro_saturated?`: 現在のサンプルでジャイロが飽和しているか。
- `dt_skipped?`: `dt` が大きすぎるため現在のサンプルを無視したか。

調整時に特に見るべき値は次の通りです。

- `max_gyro_x`, `max_gyro_y`, `max_gyro_z`: 最も大きい軸を選ぶ。
- `angle`: 1回転中に `6.0` または `-6.0` に近づくはず。
- `dt_skipped?`: 通常は false のままが望ましい。
- `phase_valid?`: 加速度フォールバックの診断に使う。ただし、false でもジャイロだけで検出できる。

## 設定メソッド

PicoRuby での互換性を保つため、コンストラクタの引数は少なくしています。追加設定は setter で変更します。

```ruby
detector = MPU6050::RotationDetector.new(:y, 120, 0)
detector.set_gyro_deadband_dps(3.0)
detector.set_max_dt_ms(50)
detector.set_accel_phase_min_g(0.25)
```

`MPU6050#rotation_detector` は同じ値を受け取り、利用可能な場合だけ setter を呼びます。

```ruby
detector = mpu.rotation_detector(:y, 120, 0, 3.0, 50, 0.25)
```

検証用サンプルでは `respond_to?` で確認してから setter を呼びます。そのため、ボード上の `rotation_detector.rb` が古い場合でも、サンプル自体は実行できます。

## チューニング手順

1. `examples/mpu_6050_rotation_verify.rb` を実行する。
2. ホイールまたはクランクを回す。
3. `max_gyro_x`, `max_gyro_y`, `max_gyro_z` を確認する。
4. 最も大きい軸を `AXIS` に設定する。
5. `gyro_dps` が選択軸に追従しているか確認する。
6. `angle_rad` が `6.0` または `-6.0` に近づくか確認する。
7. `dt_skip_count` が増える場合、ログを減らすか `MAX_DT_MS` を増やす。
8. 小さな振動でイベントが出る場合、`GYRO_DEADBAND_DPS` または `MIN_PERIOD_MS` を増やす。
9. 実際の回転を取り逃がす場合、`GYRO_DEADBAND_DPS` を下げ、軸が正しいことと `dt_skipped` が false であることを確認する。

## 既知の制限

この検出器は、完全なセンサフュージョンは行いません。Kalman filter や quaternion filter による絶対姿勢推定はしていません。使っているのは次の要素だけです。

- 選択した1軸のジャイロ積分。
- 加速度位相によるフォールバック。
- 単純なしきい値処理と最小周期フィルタ。

これは PicoRuby の組み込み用途では意図的な設計です。実装は履歴バッファを持たず、サンプリングループ中のオブジェクト確保を避けるようにしています。
